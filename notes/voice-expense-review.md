# Check a spoken expense entry

Original fictional speech-entry example. It does not claim a recognition accuracy, language list or exact app command syntax.

A fictional owner intends to record Rs 850 for transport on 5 November 2026. If the captured text says Rs 8,500, that is a difference of 8,500 - 850 = 7,650. Compare the recognised amount and description with the intended transaction before relying on the record. A plausible-looking amount can still be wrong.

Suggested checks: amount, expense description, transaction date and any vendor information actually supplied. Do not invent a vendor when the speaker did not identify one. If a statement is ambiguous, verify the underlying receipt or payment record. Check whether an earlier attempt already created a record before repeating the entry, to avoid treating a retry as another expense.

The owner approved adding expenses by speaking in Bolcash. This does not establish a specific review screen, automatic receipt attachment or speech support for every language. Describe review as a practice the user should carry out using the available records, not as a promised app screen sequence.

A guide can contrast speaking with typing while avoiding the claim that all manual work disappears. Users still need to inspect recognised details and correct errors. No speed comparison or guaranteed reduction in mistakes is supported by this fictional example. Product claims must remain within app_facts.json.
